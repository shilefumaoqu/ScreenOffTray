# 目录结构

| 目录 | 用途 |
| --- | --- |
| `app_main/ScreenOffTray` | 常驻托盘及业务，包括设置保存、显示准备、播放保护和关屏会话。Rust 播放器读取源码随播放模块维护。 |
| `app_main/ScreenOffTray.Settings` | WPF 设置界面、布局、主题及专用图标缓存 |
| `app_main/ScreenOffTray.DriverSetup` | 驱动核验、安装、卸载和恢复的业务实现 |
| `app_main/Shared` | 快捷键业务模型及三个工程使用的程序集版本元数据 |
| `app_request/ScreenOffTray` | 托盘的命令行分流、安装后启动确认 |
| `app_request/Settings` | 设置进程入口和私有命名管道的两端及协议 |
| `app_request/DriverSetup` | 安装器调用的驱动助手命令行入口 |
| `app_tools/Windows` | 共用 Windows 显示适配及程序名称解析 |
| `Installer` | Inno Setup 向导、向导素材及构建脚本 |
| `resources` | 程序图标、帮助、默认设置说明 |
| `vendor` | 固定版本第三方驱动、许可证，以及经过指纹校验的 Rust DLL 和构建记录 |
| `tests` | 当前测试、隔离工具与[入口说明](../tests/README.md) |
| `docs` | 使用、构建、版本验证和展示素材 |

根目录保留双语 README、发布说明、许可证、Git 规则及 `打包安装版.cmd`。

构建入口保持不变：`打包安装版.cmd`。如需独立验证输出，在仓库根目录运行：

```powershell
.\Installer\build.ps1 -OutputDirectory .\checks\layout-build
```

三个工程放在 `app_main/`，通过显式编译项引用 `app_request/` 和 `app_tools/`。打包器按工程相对路径读取源码，复制到干净暂存目录，再构建并核对安装包解包清单。安装路径、设置路径、程序名称、版本号和驱动材料沿用 0.2.7。

驱动助手的 `Program.Main` 负责读参数和分流，再调用 `DriverLifecycle.cs` 中的既有实现。设置进程的命令通过私有命名管道进入主程序，`SettingsUiBridge.cs` 作为托盘控制器的一部分处理业务操作，仍与托盘共用状态。

旧 WinForms 设置界面及专用测试已移出当前树，历史 Tag 保留原始版本。带版本号的文档是当时的记录，其中历史命令与路径需在对应版本使用；当前构建和测试以[构建与验证](构建与验证.md)及 `tests/README.md` 为准。

## 三目录迁移

本次从 `v0.2.7` 建立本地候选，以实体目录落实原有职责映射。保留 73 个迁移文件的原始字节。驱动助手分出命令行入口后，可用未修改的方法体重组出原始源码。

- 默认 CMD 在 Windows PowerShell 5.1 下编译三个工程。解包核对 16 个文件和临时核验助手。13 个非 EXE 文件的哈希与 0.2.7 发布包一致，包括 Rust DLL 和驱动。三个 EXE 的文件版本和程序集版本一致。
- 设置命名管道 12 项、启动确认 12 项、请求与设置事务 58 项、更新器 65 项、隔离保护 11 项及驱动助手纯自检 124 项通过。WPF 布局与解包后设置进程通过私有桌面测试。
- 专门审查发现旧 `src/` 下残留的 WPF 生成物会导致布局检查误报。调整后验证了旧生成物可保留，真正遗留的源码仍会被拒绝。
- 本次未安装候选或运行实机关屏、驱动变更、长时资源测试。下文记录的是此前整理到 `src/` 时的验证。

## 2026-11-15 迁移验证

- 三个工程共 77 个声明输入、5 个实际共享源通过路径检查；73 个迁移后的运行源码与资源保持原始字节。
- 首轮使用原固定工具缓存、PowerShell 7 完成干净暂存构建，三个工程通过；最终安装包的 14 个产品文件解包比对通过。此结果未覆盖默认入口的 Windows PowerShell 5.1 编码行为。未覆盖安装或发布新安装包。
- 请求协调 58、状态快照 13、命名管道 12、启动确认 12、WPF 隔离布局 39、版本门禁 4 项通过；隔离工具的 11 个禁止副作用保护通过自检。
- 启动确认夹具首次与其他任务并行时失败，单独复验通过；未修改测试门槛，尚无证据确定首次失败原因。
- 本地专门审查入口因宿主命令环境故障无法读取差异，改用独立只读审查，当时未发现 P1/P2；GitHub 云端审查在合并后指出 P1：PowerShell 5.1 按 ANSI 读取无 BOM 的工程文件，导致中文图标路径乱码、打包失败。该问题已在中文系统编码下复现，构建器改为显式 UTF-8 读取，新增实际读取语句的回归检查。未重复实机关屏、驱动或长期资源测试。
- 本次全新下载的上游解包工具 ZIP 与原固定哈希不符，构建按预期停止；改用此前匹配固定哈希的缓存完成验证，没有调整依赖校验值。冷下载问题不属于目录迁移修复。

P1 修复后，Windows PowerShell 5.1（ANSI 代码页 936）下三个工程的实际读取语句及图标路径检查通过；同一宿主配合原固定缓存完成干净暂存构建，最终 14 个产品文件解包比对通过。没有安装或发布这次验证产物，也未更改软件版本。

后续独立修复了上游同名附件替换导致的冷下载异常：固定 innounp 2.71.3 附件 ID、已核验的 SHA256 及独立缓存名。实际默认 CMD 在全新工具缓存下下载三项依赖、构建并解包比对 14 个产品文件通过，错误哈希仍被阻断。具体来源和验证边界见[构建与验证](构建与验证.md)。
