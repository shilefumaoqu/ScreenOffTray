# ScreenOffTray 0.2.3 · 设置主题与更新动作修复

参考：`suming-ui-reference` 的 Pane 风格包 `pane/0.1.1`，研究源固定提交 `054eb91b3365dd9834680ba26d7d21bb7757b23b`。采用方式为整体风格下的局部修正，页面范围仅限设置窗口“关于”页。

## 主题

- Pane 的产品主题是跟随系统、浅色、深色；参考手册中的几何、暖白等背景是观察玻璃的测试环境，不能作为产品主题。
- 设置窗口现显示“跟随系统／浅色／深色”。跟随系统读取 `AppsUseLightTheme`，只决定当次呈现，保存值仍为 `system`。
- 旧设置继续兼容：`geometry` 与 `warm` 映射为 `light`，`black` 映射为 `dark`。
- 浅色使用中性蓝灰 `#F6F6F8` 材质，深色使用 Pane 中性深色 `#1C1C20 → #161619`；强调色沿用 `#5874C9`。
- 没有把参考图的壁纸、外围舞台或测试背景放进产品窗口。

## 更新动作

- 发现稳定版本后，按钮从“检查更新”改为“下载安装包”，避免用户需要再次猜点击同一个按钮。
- 从 GitHub Release 的 `assets` 中只接受精确名称 `ScreenOffTray-<version>-Setup-x64.exe`、精确大小写的 Release Tag 和受信任仓库下载前缀；不匹配时仍回退到受信任的 Release 页面。
- 按钮只打开 GitHub 下载，不自动运行安装包、不自动退出程序。打开浏览器失败会在设置窗口显示错误。

## 验证边界

- WPF 隔离检查覆盖中英文主题名称、系统主题解析、浅/深颜色差异、旧产品主题入口删除和更新按钮文案。
- 更新解析夹具覆盖合法安装包资产与恶意/非预期 URL 拒绝；不访问 GitHub，不下载或执行文件。
- 未覆盖所有 Windows 主题实时切换事件；设置窗口重新打开或应用新状态时重新读取系统主题。
