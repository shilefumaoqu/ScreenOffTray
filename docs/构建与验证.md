# 构建与验证 / Build and verification

## 构建安装包

在 Windows x64 上安装 .NET Framework 4.8，打开仓库根目录，双击 `打包安装版.cmd`。也可以从 Windows PowerShell 5.1 执行：

```powershell
powershell.exe -NoLogo -NoProfile -ExecutionPolicy RemoteSigned -File .\Installer\build.ps1
```

执行策略仅应用于该次 PowerShell 进程，不修改系统策略。企业策略限制不会被绕过。

脚本首次从固定地址下载并校验 .NET 4.8 参考程序集、Inno Setup 7.1.0 和安装包解包工具，缓存于 `%LOCALAPPDATA%\ScreenOffTray-Build\Tools`。构建需联网或已备好缓存；最终用户安装包可离线使用。

每次构建从新的 `打包暂存\build-*` 目录编译，只收集白名单文件，并解包核对实际安装包内容。输出为：

```
安装包/ScreenOffTray-0.1.4-Setup-x64.exe
安装包/安装内容清单.json
安装包/打包验证.json
```

清单和构建回执含构建机路径，供本地检查，不应直接作为公开日志上传。原始驱动三文件的 SHA-256 固定在构建脚本中；不要修改 INF、重签 CAT 或加入其他驱动。

## 纯计时测试

`tests/AutoOffTimingTests.cs` 只测试虚拟时间和纯辅助类，不执行主程序、原生显示 API、键鼠钩子或设置读写。在仓库根目录执行：

```powershell
$testExe = Join-Path $env:TEMP ('ScreenOffTray-timing-' + [guid]::NewGuid().ToString('N') + '.exe')
& "$env:WINDIR\Microsoft.NET\Framework64\v4.0.30319\csc.exe" /nologo /langversion:5 /checked+ /warnaserror+ /target:exe /platform:x64 /main:ScreenOffTray.AutoOffTimingTests "/out:$testExe" .\AutoOffTiming.cs .\tests\AutoOffTimingTests.cs
if ($LASTEXITCODE -ne 0) { throw 'Test compilation failed.' }
& $testExe
if ($LASTEXITCODE -ne 0) { throw 'Timing tests failed.' }
```

完整现场诊断、个人配置和历史测试产物未纳入公开仓库。已有其他定向验证的范围见[验证与限制](验证与限制.md)，不把这一份纯测试当成产品端到端验证。

## English

On Windows x64 with .NET Framework 4.8 installed, open the repository root and run `打包安装版.cmd`, or use the PowerShell command above. It uses the existing C# 5 projects, downloads and verifies pinned build tools, builds in a clean staging directory, then extracts and verifies the final installer. Downloads are cached under `%LOCALAPPDATA%\ScreenOffTray-Build\Tools`; only building needs the tools, not installing the application.

The output is `安装包/ScreenOffTray-0.1.4-Setup-x64.exe`, with a payload manifest and local build receipt. These receipts contain local paths and should not be published without review. Signed driver inputs must remain unchanged.

The second command block compiles and runs only the virtual-time timing test, outside the application entry point. It does not launch the product, access settings or invoke native display operations. This test does not prove hardware behavior. Private diagnostic records and historical test outputs are intentionally absent from this repository.
